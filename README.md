# ЧитКод

Трекер прочитанных страниц книжного клуба «БИОМ», Великий Новгород.
Слоган — «Читай вместе с БИОМ». Имя будущего чат-бота — «Биомчик».

Одна строка — один участник: ФИО, текущая книга, суммарно прочитано, уровень
с прогресс-баром, недельная динамика, цитата и место в рейтинге. Таблицу видит
любой по ссылке, редактировать можно только свою строку.

---

## Запуск одной командой

```bash
cp .env.example .env      # поменяйте SECRET_KEY, POSTGRES_PASSWORD и CHITKOD_DOMAIN
docker compose up -d --build
```

Поднимутся четыре сервиса: `db` (PostgreSQL 16), `web` (Flask + Gunicorn,
миграции применяются автоматически при старте), `worker` (пересчёт челленджей)
и `caddy` (HTTPS с автоматическим Let's Encrypt).

По умолчанию приложение доступно на `http://localhost:8080`. На реальном домене
укажите его в `CHITKOD_DOMAIN`, откройте порты 80 и 443 — сертификат Caddy
получит сам, настраивать ничего не нужно.

### Первый администратор

```bash
docker compose exec web flask create-member "Иван Иванов" --admin
```

Команда напечатает персональную ссылку. Перейдите по ней, придумайте PIN — и
у вас есть админка на `/admin`.

### Демо-данные

```bash
docker compose exec web flask seed --reset     # ВНИМАНИЕ: стирает текущие данные
```

Создаст семь участников и записи за три недели так, чтобы сразу было видно всё
интересное: точные границы уровней (5000, 2000, 1000), равенство сумм с
тай-брейком, рост, падение, «старт», «пауза», помеченную для проверки запись,
книги на полке прочитанного, цитаты и три челленджа.

Команда напечатает персональные ссылки всех участников — **больше они нигде не
показываются**, сохраните их сразу.

## Аватарки уровней и логотип

Картинки лежат в `app/static/`. Сейчас там временные SVG-заглушки — положите
свои файлы **под теми же именами**, в коде менять ничего не нужно:

| Файл | Уровень | Порог |
|---|---|---|
| `app/static/levels/level0.svg` | Новичок | 0 |
| `app/static/levels/level1.svg` | Младенец | 100 |
| `app/static/levels/level2.svg` | Первые шаги | 500 |
| `app/static/levels/level3.svg` | Жёлтый рейнджер | 1 000 |
| `app/static/levels/level4.svg` | Колобок | 2 000 |
| `app/static/levels/level5.svg` | Паучок | 5 000 |
| `app/static/levels/level6.svg` | Хранитель Биома | 10 000 |
| `app/static/logo.svg` | логотип клуба | — |

Если файлы будут в PNG, поменяйте расширение в таблице `levels`
(колонка `avatar_file`) — например, `update levels set avatar_file =
'level3.png' where idx = 3;`. Названия уровней и пороги тоже правятся прямо
в базе, без переразвёртывания.

## Как всё устроено

**API-first.** Вся бизнес-логика живёт в `/api/v1/*`. Веб-страницы — тонкий
клиент: они вызывают те же эндпоинты, что вызовет чат-бот и мобильное
приложение. Ни одной формулы в шаблонах нет.

**Итоги не хранятся.** Суммарные страницы, недельная динамика, уровень, стрик
и место в рейтинге всегда считаются агрегацией из `reading_entries`
(`app/domain/leaderboard.py`). Отдельного поля «всего прочитано», которое можно
рассинхронизировать, в базе нет.

**Челлендж сменяется без крона.** Текущий челлендж выбирается запросом
`where week_start = <текущий понедельник по Москве>`. В понедельник 00:00 МСК он
меняется сам, даже если планировщик лежал. `worker` нужен только для пересчёта
числовых результатов и подведения итогов недели.

**Время.** В базе всё в UTC (`timestamptz`), недели и «сегодня» считаются по
Europe/Moscow. Неделя — понедельник 00:00 … воскресенье 23:59:59.

**Доступ.** Персональная ссылка с токеном + четырёхзначный PIN, который участник
придумывает сам при первом входе. Дальше — подписанная cookie на 90 дней
и кнопка «Это не я» в шапке. Токен хранится хешем, PIN — scrypt, после пяти
неудачных попыток пауза 15 минут. Перевыпуск ссылки мгновенно разлогинивает все
устройства участника.

### Структура

```
app/
  domain/          вся бизнес-логика, не знает про HTTP
    time_utils.py    недели и московское время
    levels.py        уровни и прогресс
    leaderboard.py   рейтинг, недельная динамика, стрик
    entries.py       журнал чтения: добавить, править, дочитать книгу
    challenges.py    челленджи недели
  api/             REST /api/v1 — единственная точка входа для записи данных
  views.py         серверные страницы, только чтение
  models.py        схема БД
  templates/       Jinja2
  static/          CSS, JS, аватарки уровней
migrations/        Alembic
scripts/           backup.sh, restore.sh, entrypoint.sh
tests/             87 тестов по критериям приёмки
```

## Бэкап и восстановление

```bash
./scripts/backup.sh                                  # дамп в ./backups, хранит последние 14
./scripts/restore.sh backups/chitkod-20260825-120000.sql.gz
```

Ежедневный бэкап в 4 утра — строкой в crontab на сервере:

```
0 4 * * * cd /path/to/chitkod && ./scripts/backup.sh >> backups/backup.log 2>&1
```

Экспорт всех данных в CSV — кнопкой в админке или `GET /api/v1/admin/export.zip`
(архив из семи CSV-файлов, с BOM — Excel открывает кириллицу без плясок).

## API

Публичное, без авторизации:

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/v1/leaderboard` | вся таблица со всеми показателями |
| GET | `/api/v1/members/<id>` | одна строка + книги участника |
| GET | `/api/v1/levels` | уровни и пороги |
| GET | `/api/v1/quotes` | стена цитат |
| GET | `/api/v1/challenges/current` | челлендж этой недели |
| GET | `/api/v1/challenges` | архив и очередь |
| GET | `/api/v1/feed` | лента событий клуба |
| GET | `/api/v1/stats` | сводка по клубу |

Вход:

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/auth/check-token` | проверить ссылку до ввода PIN |
| POST | `/api/v1/auth/set-pin` | первый вход: задать PIN |
| POST | `/api/v1/auth/login` | вход по ссылке и PIN |
| POST | `/api/v1/auth/logout` | «Это не я» |
| GET | `/api/v1/auth/me` | кто я сейчас |

Своя строка (нужен вход):

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/entries` | **+N страниц** или `percent` для электронной книги |
| PATCH/DELETE | `/api/v1/entries/<id>` | правка своей записи в течение суток |
| PATCH | `/api/v1/members/me` | сменить ФИО |
| POST | `/api/v1/books` | завести текущую книгу |
| POST | `/api/v1/books/<id>/finish` | «Книга дочитана» |
| POST | `/api/v1/quotes` | добавить цитату |
| POST | `/api/v1/challenges/<id>/claim` | отметить «мягкий» челлендж |

Админ: `/api/v1/admin/members`, `.../members/<id>/link`, `.../entries/flagged`,
`.../challenges`, `.../challenge-results/<id>/confirm`, `.../export.zip`.

### Авторизация для бота и мобильного приложения

`POST /api/v1/auth/login` возвращает `session_token`. Дальше — заголовок
`Authorization: Bearer <session_token>`, никаких cookie и CSRF:

```bash
TOKEN=$(curl -s -X POST https://example.org/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"token":"…из ссылки…","pin":"1234"}' | jq -r .session_token)

curl -X POST https://example.org/api/v1/entries \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"pages": 37, "note": "перед сном"}'
```

Запросы из браузера ходят по cookie и требуют заголовок `X-CSRF-Token`
(его ставит фронтенд сам).

## Правила, зашитые в логику

* Запись — от 1 страницы. Больше 300 за раз сохраняется, но помечается для
  админа. Больше 10 000 отклоняется как заведомая опечатка.
* Дату чтения нельзя поставить в будущее и дальше 30 дней назад.
* Свою запись можно править и удалять 24 часа, дальше — только через админа.
  Удаление мягкое: из подсчётов уходит, из истории клуба нет.
* Электронная книга: `percent` пересчитывается в страницы по объёму книги,
  а если объём не указан — по условным 300 страницам.
* Тай-брейк в рейтинге: при равной сумме выше тот, кто достиг её раньше.
* Недельная динамика: прошлая неделя 0 и текущая больше нуля — «старт»;
  обе нулевые — «пауза»; иначе процент, зелёный или красный.

## Разработка

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
export DATABASE_URL="sqlite+pysqlite:///$(pwd)/dev.sqlite3" SECRET_KEY=dev FLASK_APP=wsgi.py
.venv/bin/python -m flask seed          # демо-данные
.venv/bin/python -m flask run --port 5000
.venv/bin/python -m pytest -q           # тесты
```

Тесты гоняются на SQLite и сервер БД не требуют. Отдельный тест
(`tests/test_migration.py`) прогоняет миграцию по-настоящему и сверяет
получившуюся схему с моделями, чтобы они не разъехались.

## Что осознанно не вошло в MVP

* Чат-бот в Telegram/VK — под него готов API, самого бота нет.
* Мобильное приложение.
* Загрузка обложек книг и фотографий участников.
* Комментарии и лайки к цитатам, ответы на цитаты.
* Поиск по книгам и подтягивание данных из внешних каталогов.
* Личные сообщения, email- и push-уведомления.
* Восстановление доступа без администратора.
* Несколько клубов в одной установке, роли сложнее «участник/админ».
* Аудиокниги в минутах — считаем только страницы и проценты.
* Тёмная тема и локализация интерфейса.
* Правка задним числом дальше 30 дней, импорт истории из таблиц.
